# AI report wallet pricing and retirement

AI reports use integer-cent wallet prices. The default is 990 cents; each new report freezes its topic's current price. Existing reports retain their price. `pointsPrice` remains zero in responses for older clients; points no longer grant report access or purchase reports. `POST /api/v1/payments/ai-report` returns business code `41001` without touching payment or points rows.

## API and payment mode

- `GET /api/v1/ai/admin/products`: human `platform_super` only, returns `code,title,subtitle,priceCents,revision,enabled,version`.
- `PUT /api/v1/ai/admin/products/:code`: `{priceCents,revision}`. Amount is an integer in `[1,100000000]`. Optimistic revision conflict is `40931`. Each changed price is audited with actor, old/new cents and revision. Updating a product never reprices an existing report.
- Existing checkout endpoints are reused with `orderType=ai_report`, `orderNo=report.reportNo`, `expectedCents`, and the quote's `balanceChannel`.
- Formal mode uses `balance`; the existing isolated demonstration-wallet mode uses `demo_balance`. No global wallet configuration is changed. `mock` (no debit) is unavailable for AI reports, including when enabled for other order types. No new payment idempotency namespace is introduced.
- Insufficient balance is `40901`; stale amount/status is `40902`; unavailable channel is `40903`.
- A previously paid report returns its original valid payment and actual paid amount without another growth quotation. Matching payment retries remain idempotent across a later wallet-mode change.
- Historical `balance`, `wechat`, `alipay`, and funded `demo_balance` purchases retain access. A demo payment needs the matching negative wallet debit ledger. Unsupported historical mock payments fail closed and require separate operator reconciliation; this release does not mutate them.
- Valid growth discounts use the frozen `growth_transaction` gross and paid values. Refunds in `pending`, `processing`, or `success` revoke access; failed refunds do not. Report detail, list and follow-up access use the same entitlement predicate.

## Migration and release order

1. Back up the affected databases using the operator's private recovery procedure.
2. Apply `scripts/db/20261026_ai_report_wallet.sql` as the database administrator. It adds `ai_report_product.price_revision`, `ai_report_price_audit`, `ai_report_points_retirement`, and read grants for AI entitlement checks. It changes defaults only; it does not delete reports, refund points or reprice history. Reapplication is tested.
3. Verify the receiver contract generated by `python3 scripts/ci/release.py contract`. The existing contract automatically covers `db/` and `scripts/db/`; there is no manual path registry.
4. Deploy the verified backend and clients. Confirm the old points endpoint returns `41001` before preparing the retirement plan. Do not run old binaries that can spend AI points concurrently with retirement.
5. Generate, review, privately back up and apply the fixed cleanup below. Runtime health alone is not payment acceptance. No live charge or cleanup is performed by the test suite.

## Approved one-off points retirement

The operator binary is `services/commerce/payment-service/cmd/retire-ai-report-points`. Recovery CI publishes `retire-ai-report-points-linux-amd64` and its SHA-256 as separate private draft assets alongside the unchanged runtime archive. `--version` reports the build source SHA. Verify source and binary hashes before use.

The CLI is deliberately fixed to batch `ai-report-wallet-20261026`: **35 reports, 43 original debit rows, 430 points, 2 exclusive sessions, 6 messages**. It offers no flags to broaden those values. Credentials are accepted only via `AI_REPORT_CLEANUP_DSN`; never put a DSN in a command, log, manifest, or chat. The client forces `charset=utf8mb4` and preserves exact timestamp strings. Paths below are placeholders for an operator-owned private directory, not a public artifact archive.

```
retire-ai-report-points --mode plan --manifest /private/operator/manifest.json --backup /private/operator/backup.json
retire-ai-report-points --mode apply --manifest /private/operator/manifest.json --backup /private/operator/backup.json
retire-ai-report-points --mode rollback --manifest /private/operator/manifest.json --backup /private/operator/backup.json
```

`plan` is read-only and writes new files exclusively with permissions 0600, fsync and checked close. The private backup includes the original scoped rows and report/follow-up content; do not upload it. The manifest contains identifiers, counts and the full private snapshot fingerprint, not report content. Copy and independently verify the backup before `apply`.

Guards require: original negative `redeem` rows with exact `ai-report:<report_no>` keys; ready points-only reports; no payment/growth references even for orphan debit rows; no previous retirement refund under any batch; exclusive same-owner report follow-up sessions with exact `报告追问 · <title>` names; no in-flight messages/runs; and unchanged rows/accounts/latest ledger IDs since the reviewed plan. A changed count or fingerprint aborts; never silently regenerate or expand an approved apply.

`apply` uses a global database named lock, a serializable transaction, row locks, per-original-entry refund ledger keys and an immutable batch fingerprint. It credits all 43 original debits including the 8 orphan debits; deletes only the selected reports and their exclusive session/message/run/tool content; retains original points ledgers, all usage/cost logs, counters, valid cash/demo purchases and other conversations. The accounting receipt and all deletions/refunds commit together. Same-batch retries are idempotent. Cross-batch reuse is refused, including after rollback.

`rollback` restores the original content rows and adds compensating negative ledger entries; it never deletes accounting history. It refuses to overwrite rows or cross any later account transaction/balance change. This is intentionally stricter than restoring an old balance snapshot. If later user activity occurred, stop and reconcile separately rather than forcing rollback.

## Verification

`bash scripts/test-ai-topic-reports.sh` uses a disposable local MySQL database. It tests generation through a synthetic model endpoint, price snapshots/CAS, production service privileges, wallet insufficient funds/concurrency/idempotency, both balance modes, discounted/historical entitlements, refund states, and cleanup snapshot guards/atomic failure/concurrent retries/cross-batch rejection/rollback. Synthetic output is not live model quality acceptance. This script is a required gate in both normal deployment and recovery package workflows.
