## 产品范围

| 模块 | 当前能力 |
| --- | --- |
| 智能体配置 | 名称、默认文字模型、全局回答要求、输出上限；独立草稿与已发布版本 |
| 技能与工具 | 启停已有技能、编辑提示词、选择是否使用已绑定工具、查看输入契约；通用兜底技能必须保留 |
| 调试工作台 | 原流程调试、Eino 工具调用验证、缺资料暂停/补充/继续、状态与结果查看 |
| 运行记录 | 用户问事与后台调试分开；用户运行的技能版本、耗时、已有用量/成本、工具轨迹 |
| 版本发布 | 调试门槛、发布说明、配置快照查看、历史版本回滚、恢复原始配置、操作审计 |

工具只能从服务端已有技能契约中选择，后台不能任意增加工具地址或执行代码。模型密钥继续由已有「模型连接设置」管理，本模块不复制密钥表单。

**发布配置仍使用现有“工具计算 → 模型回答”执行流程。Eino 仅在管理员调试工作台启用，尚未切换用户端。** 管理台调试通过轮询展示阶段和结果；用户问事原有 SSE 协议不变。

## 操作流程

1. 在模型连接设置中配置可用模型，进入智能体配置并保存草稿。修改技能后也需保存。
2. 使用合成资料运行「原流程调试」。同一草稿修订号、同一模型设置修订号在过去 24 小时内有成功记录，才允许发布。模型设置或草稿变更后需重测。
3. 填写说明并发布。草稿保存不影响用户端；发布仅在服务端启用开关后生效。此门槛是基本可运行检查，不等同于完整质量评估。
4. 在运行记录查看错误、耗时、工具调用与已有用量。Eino 的模型/工具次数是尝试次数；未采集的 token 不作为零费用展示。
5. 出现问题时填写原因，回滚到指定历史版本或「原始问事配置」。发布、回滚和保存均有审计。

保存和发布采用修订号并发检查，冲突不会覆盖另一位管理员的修改。离开未保存页面会提示。发布版本冻结技能输入契约和提示词；一次请求及其异步执行保持该版本，下一轮请求可以使用新版本，并非整个多轮会话永远固定在首个版本。

## 数据库与上线步骤

迁移文件：`scripts/db/20260928_ai_agent_operations.sql`。新增 `ai_agent_workspace`、`ai_agent_version`、`ai_agent_audit`、`ai_agent_debug` 四张表，可重复执行。请针对 AI 服务现有数据库执行，脚本没有硬编码 `USE`。

上线顺序：

1. 备份目标数据库，在正确数据库执行新增表迁移。
2. 部署 AI 服务和平台管理台；保持 `AI_AGENT_OPERATIONS_ENABLED=false`（默认值）。管理台可保存和调试，用户端继续原始配置。
3. 用真实模型、真实 MCP 和合成资料验证配置、工具契约、暂停恢复、失败与超时行为，再发布候选版本。
4. 确认后在实际部署配置中设置 `AI_AGENT_OPERATIONS_ENABLED=true`，重新创建 AI 服务容器使环境变量生效。`docker-compose.full.yml` 已接入该变量。
5. 验证新请求使用发布版本、原有 SSE/重试可用、运行记录包含 `@a<版本号>`。

回退可通过管理台回滚到版本 0（原始配置），也可关闭开关并重新创建 AI 服务容器。开关关闭时原问事路径不读取新版本表；启用后若版本存储不可用，请求明确失败，不静默绕过已发布策略。

本次只完成本地实现与验证，未执行线上迁移、推送或部署。

## 接口与权限

前缀：`/api/v1/ai/admin/agent`。

| 方法 / 路径 | 用途 |
| --- | --- |
| GET /、PUT / | 读取工作区、保存草稿 |
| POST /publish、POST /rollback | 发布、回滚 |
| GET /versions/:id | 版本与可编辑配置快照 |
| GET /debug、POST /debug | 调试记录、启动调试 |
| GET /debug/:id | 调试状态与结果 |
| POST /debug/:id/resume、POST /debug/:id/cancel | 补充资料继续、取消待补充任务 |
| GET /runs、GET /runs/:id/tools | 分页用户运行记录、工具轨迹 |

权限在既有网关和服务内分别校验。服务仅接受可信网关注入的用户身份，不能向公网直接暴露 AI 服务并信任客户端身份头。响应均禁止缓存；请求拒绝未知字段、过大正文；数据库错误与工具上游错误不直接返回。

用户运行记录不返回原始问题、出生资料、工具结果正文。后台调试存储结果和事件，不存储输入问题/结构化资料；模型输出仍可能复述输入，调试应使用合成资料。调试历史仅查询最近 30 天，新调试启动时分批清理过期记录（每次最多 1000 条），当前没有独立定时清理任务。

## Harness 边界

- Eino 支持当前已绑定工具的 `bazi`、`ziwei`、`qimen` 技能；资料由用户确认的结构化输入提供，模型不能代填事实。
- 每次执行/恢复外层 50 秒，Eino 段内 45 秒；模型/工具各最多 4 次尝试，Eino 单次输出上限最多 512 token，且受配置约束。
- 单实例最多 8 个内存任务；每位管理员同时最多一个进行中或待补充任务。恢复/取消校验创建者和中断状态。
- 检查点只在进程内，10 分钟过期。重启后历史结果仍在，但进行中/待补充任务会显示已失效，需要重新调试。多实例调试需要会话粘性；持久检查点尚未实现。
- 目前没有可视化工作流编排、自动评估集、流量灰度、长期记忆、多智能体编排或 Eino 精确 token/费用计量。上述能力不应被描述为已经交付。
