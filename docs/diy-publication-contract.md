# DIY 定稿发布契约（2026-10-20）

发布前提：本人设计的同款订单已付款成功（支持真实付款与模拟付款），商城台审核通过进入制作（或后续正常履约状态），订单保存的设计与价格快照完整，当前草稿的珠子顺序、规格、绳线、手围、松量与订单定稿一致。未付款、待审核、取消、售后、退款中及已退款均不符合。审核通过是既有“款式、用料和价格已确认”的业务节点，没有增加第二套确认流程。 同款有多笔订单时，优先使用仍有效的真实付款定稿，避免后续模拟测试覆盖原有返利资格；真实订单失效后仍可使用合格模拟订单展示。

## 客户端字段

`GET /diy/my-designs` 和本人 `GET /diy/designs/:id` 返回：

```json
{
  "revision": 4,
  "status": "public",
  "sourcePublicationId": 0,
  "publicationEligibility": {
    "canPublish": true,
    "reason": "ready",
    "message": "订单已付款且款式、用料和价格已确认，可以发布",
    "orderId": 25,
    "orderNo": "DIY...",
    "designRevision": 2
  },
  "publication": {
    "id": 9,
    "designRevision": 3,
    "materialFee": 320,
    "publishedAt": "2026-10-20 15:00:00"
  },
  "draftChanged": false
}
```

- `publicationEligibility` 只返回给本人。`canPublish` 是唯一发布门槛，客户端禁止根据订单数量、`orderStatus` 或其他字段猜测。未知或缺失字段须关闭发布操作。
- `reason` 是可扩展字符串：`ready`、`order_required`、`payment_required`、`confirmation_required`、`design_changed`、`order_inactive`、`snapshot_unavailable`、`moderation_required`。展示 `message`，按平台既有简繁转换。
- `orderId`、`orderNo` 仅本人可见。`designRevision` 是订单定稿中记录的设计版本。
- `publication` 是当前有效公开版本的标识，不包含他人订单号、支付信息、地址。缺失时没有有效公开版本，`draftChanged=false`。
- `draftChanged` 表示可编辑稿与当前有效公开快照不一致；公开状态与草稿是否更新是两回事。
- `sourcePublicationId` 由后端复制生成，不允许保存请求指定，也不代表复制者具备发布资格。

## 读写行为

- 广场列表只返回有效发布快照。旧作品没有合格定稿发布记录时不进入公开列表；本人仍可打开原草稿，接口的有效 `status` 返回 `private`，不批量修改旧数据库状态。
- 作品详情/分享统一 `GET /diy/designs/:id?view=published`，即使查看自己的作品也只读公开快照。默认详情：本人返回可编辑稿，其他人返回有效公开快照。没有有效公开快照返回既有未找到错误。
- `POST /diy/designs` 只保存草稿，不改变已发布定稿。已有公开作品保存后仍公开，定稿不变。下架必须使用状态接口。客户端无需发送 `status`。
- `PUT /diy/designs/:id/status` 请求仍为 `{ "revision": 4, "status": "public" }` 或 `"private"`。事务锁设计与合格订单重新校验，不接受客户端指定确认订单。资格失效返回 `40915` 和中文提示，版本冲突仍为 `40914`。
- 发布与新的下单归因按设计/订单、payment、refund 的顺序显式加锁，并在锁后重读付款/退款状态；直接余额退款与下单按同一 payment 行序列化。外层查询的 `EXISTS` 不是跨服务并发校验的替代品。
- 发布生成不可变版本并原子切换公开指针。下架不删除历史定稿与返现凭证。订单取消/退款/售后立即停止公开读取和新的定稿归因。
- `POST /diy/designs/:id/copy` 从有效公开快照复制；本人未发布作品可复制自己的草稿。副本始终为私有，无自己的发布资格。
- 已付款并确认的款式，即使当前材料已售罄，仍可发布；他人下单继续执行现有库存与现价校验。公开不代表可立即购买。
- 管理端下架作品返回 `moderation_required`，修改草稿后重新计算资格；管理端直接发布也不能越过本人付款与定稿门槛。
- 旧的私人 V1 用料清单可按原清单下单，但没有完整款式顺序的旧快照不能取得发布或返现资格。

## 提示文案

| reason | message |
| --- | --- |
| ready | 订单已付款且款式、用料和价格已确认，可以发布 |
| order_required | 完成设计并下单，付款且确认款式、用料和价格后可发布 |
| payment_required | 订单完成付款后才可发布 |
| confirmation_required | 订单已付款，待确认款式、用料和价格后可发布 |
| design_changed | 草稿已修改，请为当前款式下单并完成付款与定稿确认后发布新定稿 |
| order_inactive | 定稿订单已取消、退款或处于售后中，暂不可发布 |
| snapshot_unavailable | 订单缺少有效定稿快照，请重新下单并确认当前款式 |
| moderation_required | 作品已被管理端下架，请修改草稿后重新确认发布资格 |

## 定稿一致性

款式指纹取 V2 文档的有序珠子 `materialId + spec`、绳线 `materialId + spec`、`wristSizeMm`、`fitAllowanceMm`，规范序列化后计算 SHA-256。忽略临时 slotId、名称、说明、渲染数据和客户端价格。单纯改名称/说明允许从已确认同款订单发布新定稿，同时保留旧版内容。

确认订单必须属于该设计和该用户，订单设计快照必须包含有效版本。价格快照的逐项材料、规格、数量必须完全等于款式用料；逐项非负单价的合计必须等于订单材料费，材料费、附加服务费、总额与订单及价格快照一致。资格不由 revision 相同或“有订单”单独决定。

## 价格与返现

公开展示与返利来源分别校验：经审核定稿的 `mock` / `demo_balance` 订单可以发布，作品可浏览、复制及下单；返利来源仍只接受真实付款的有效定稿。模拟来源作品的直接下单、复制下单及同款转发不生成真实返利，即使下游买家使用真实付款也不会把模拟来源变为可返利来源。修改款式并完成自己的真实付款与确认后，可按既有规则形成新款来源。

公开 `totalPrice` 与 `publication.materialFee` 均取确认订单的材料价，珠子单价与用料取同一订单价格快照。它是定稿材料参考价，非新的永久锁价承诺；再次下单仍按现有服务端库存、现价和优惠复核。

复制与下单在服务端绑定不可变 `sourcePublicationId`。只有使用该定稿配方（含珠子顺序、规格、绳线、手围、松量）才可沿用来源返现；改变款式的草稿不能悄悄沿用旧款归因。订单快照及新返现记录保存定稿版本 ID，结算不再追逐可变草稿的复制链。自身购买、模拟支付、退款、等待期、比例及上限沿用既有规则，不回算旧财务流水。

A 的定稿被 B 同款复制、自己付款确认再发布，C 使用 B 的同款仍归因 A；公开作者 B 与返现受益人 A 分开存储，接口不额外公开财务归属信息。B 改款并完成自己的付款与确认后发布，才形成归属 B 的新款。来源失效后同款转发或重新发布不能清洗来源。

公开详情只读取作者当前发布指针；返现归因允许读取已被新版替换但仍有效的不可变根版本。例如 A 发布 v2 后，B 的 A-v1 复制款仍沿用 A-v1，前提是 A 未下架且 v1 的确认订单有效。明确下架、管理端下架、该版本的取消/售后/退款停止新的归因。既有订单和返现记录的版本绑定不改，后续结算/退款继续走原订单规则。

返现计算分母仍为既有规则中的净材料费（材料费扣除该订单的成长优惠），不计附加服务费；比例、上限、等待期、模拟支付及自购排除沿用既有实现，没有新增财务比例或永久价格承诺。

发布部署与验收步骤见 [DIY 定稿发布迁移](diy-publication-deployment.md)。
