# 模拟钱包：功能、验证与部署

本次整合基于线上后端 a6e84eb、H5 dc00d2c、原生/管理台 32b5990，先合入此前未上线的余额收银台代码，再增加独立模拟资金。

## 用户怎么用

1. 我的 → 钱包 → 测试余额（模拟）→ 模拟充值。单次 1～5000 元，仅记入测试账户。
2. 预约、即时咨询、商城、DIY 和付费 AI 报告统一打开收银台；明确选择模拟余额并确认扣款。余额不足不能支付，取消保留待付款订单。
3. 订单按原有业务流程取消/退款，成功后退回测试余额。余额流水可查看充值、扣款与退款，演示账单可回到关联订单。
4. 原充值记录可在可用余额内撤回一次测试充值；不向微信、支付宝或银行转账。
5. 寺院/大师钱包切换“模拟余额结算”，查看自己的结算份额并确认模拟提现。即时咨询必须结束/到期后才可模拟提现。预约结算沿用服务完成并评价后的现有触发点。
6. 总后台财务概览展开“模拟钱包资金”，查看独立收款、退款、平台费用和最近 30 条结算。

H5、iOS 信众端、H5/iOS 大师端、寺院后台和总后台均有对应入口。旧版原生客户端必须更新：开启模拟余额后旧的直接 mock 支付入口明确拒绝，避免绕过扣款。

## 资金边界

- `demo_wallet_account/ledger/recharge` 与真实 `wallet_*` 分表，独立余额和幂等键。
- 支付渠道为 `demo_balance`，真实渠道为 `balance`，原演示账单 `mock` 保留。
- 模拟收款、分账、提现进入 `demo_finance_* / demo_settlement / demo_withdrawal`，不发布正式大师收益累计事件，不奖励可兑换积分。
- 没有调用外部支付或银行接口。测试余额不可自动转为真实余额。
- 支付金额从服务端订单读取，以分计价。所有权校验、事务锁、稳定请求号防止篡价、重复扣款和超额使用。
- 钱包订单退款当前为整单退。已产生服务结算的订单不允许直接退款，避免提现后又退回余额。部分订单退款、结算后冲正及真实银行提现不在本次开放范围内。
- 充值退款失败不改变账户；同一退款重试不会再次扣减。接口/数据库错误会回滚资金与订单变动。

## 启用顺序

1. 备份数据库与 payment/finance 配置。取得合法可用的数据库管理员配置。
2. 按顺序执行 `scripts/db/20260926_balance_wallet.sql`、`scripts/db/20260928_demo_wallet.sql`；还需保留既有 `20260926_wallet_identity_permissions.sql` 的大师身份最小权限。
3. payment 配置：`AppEnv: development` 或 `demo`，`Provider: mock`，`Wallet.DemoEnabled: true`，`Wallet.Enabled: false`，微信/支付宝 Enabled 均 false。production/live 与模拟余额互斥，启动配置校验会拒绝混用。
4. finance 配置：`DemoWalletEnabled: true`。先完成数据库迁移，再一起部署 payment、finance、booking 与各 Web 端；原生交付源码供用户构建。
5. 用专用测试账号验收充值→付款→取消/退款→服务完成→结算→模拟提现；核对真实钱包、正式积分和总账未变化。
6. 回滚先关闭演示入口并回滚配套前后端配置/版本；保留账表和测试流水，不做删除或资金转换。
